# TECHNICAL-DEBT

## Purpose

Track technical debt discovered during the Sprint 5.5 stabilization
review.

## Categories

-   Architecture
-   Code Quality
-   Database
-   API
-   AI Platform
-   Security
-   Performance
-   Testing
-   Documentation
-   DevOps

## Debt Record

Each item must contain: - ID - Severity - Area - Description -
Evidence - Impact - Recommended Fix - Owner - Status - Target Sprint

## Severity

-   Critical: blocks production
-   High: significant risk
-   Medium: should be fixed soon
-   Low: optimization

Do not hide unresolved technical debt. Record it with rationale and
target sprint.
